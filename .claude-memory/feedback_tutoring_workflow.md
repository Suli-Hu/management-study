当用户以"老师模式"让我讲解经营学知识时，按以下工作流执行。

**Why**：用户是备考旧帝大+早慶神戸一橋经营学研究科的中国留学生，需要系统化、可控的学习节奏，既要覆盖考试面也要能产出知识卡片沉淀到 `management-study` 项目的 v2 数据中（`v2/data/keiei/kp/{id}.json`，已替代 V1 的 data.js）。

**How to apply**：

### 1. 按学派推进（不是按主题随机跳）
用户每次点题一个学派，按该学派一个完整周期走完，再换下一个。

### 2. 总揽阶段 — 取"过去问 ∪ 三国教材"的并集
用户点题学派后：
- **搜过去问**：翻 `/Users/husuli/Documents/Web Project/References/Other/Past_Exam_Questions.pdf` 和 `Graduate_Business_Past_Exams.docx`
- **对标教材**：用 References 下的 Organization / Strategy / HRM / OB / Other 分类 PDF，加上我训练中的中美日主流经营学教材知识
- **取并集**：两边任一来源出现的 KP 都进清单，标注来源（真题 / 教材 / 二者均有），不因"只在某一边"就剔除
- **整体导读**：讲学派脉络、关键人物、批判对象、时代背景
- **此阶段不做** data.js 现状对比——用户明确说过那和"学习"无关，留到第 4 步

### 3a. 每隔 3–4 个 KP 做一次 callback（2026-04-19 用户立规）
- 每推进 3–4 个 KP，在下一个 KP 开讲前**插一个综合回顾**：用 1–2 个跨 KP 串联问题检验学习者是否能把散点连成网
- 形式举例：给一个真实案例让用 Lewin + Kotter + 组织惯性 + 力场分析**联动解释**；或让用户用时间线把几个理论按历史脉络排序并说清因果；或做"如果没有 X 理论，Y 理论会怎样"的反事实提问
- 回顾完成后再进入下一 KP 的 6 步流程
- 计数以"新讲 or 深讲的 KP"为准，小改动·删改不计入

### 3. 每个 KP 的标准闭环 — 6 步走（2026-04-19 确立）
用户圈定范围后，按以下 6 步一个一个 KP 走完再进下一个：

1. **讲 KP**：定义 → 核心内容 → 考场答题要点（必要时点志望校倾向）
2. **🆕 用户答疑回合**：讲完主动邀请「有什么想问的？」，等用户提问，我答疑；用户说「没问题了」或直接提问后再等到完整答疑结束，才进下一步
3. **抛 1–2 个小问题（我考用户）**：形式必须换样子，不能每次"回头考定义"。轮换：概念辨析 / 反例举出 / 情境应用 / 跨理论对比 / 英译中 / 日译中 / 图表复原 / 判断正误 / 续写因果链 / 给学者找论点 / 原文引文填空……
4. **用户答题**
5. **反馈 + 小结**：点评答案 + 提炼该 KP 的记忆锚点
6. **生成 3 颗粒度卡片 + v2 KP JSON**：
   - 🔴 **必须用真实渲染的高保真 demo 页给用户看**（按 [CONTRIBUTING.md §8 原则 2](Main/CONTRIBUTING.md)），**禁止**用纯文字描述颗粒度让用户选
   - 做法：v2 admin UI（`/keiei/kp/new` 即时渲染）或 `v2/public/demo_granularity.html` 临时页，通过 Claude Preview 视觉对比
   - 三种颗粒度：A 叙述（一段话）/ B 平铺（3–5 条）/ C 手风琴 or 对比卡（多分组展开）
   - 每个方案底下附上 KP JSON 字段（`id` / `title.zh` / `title.en?` / `title.ja?` / `body.zh` / `body.ja?` / `schools[≥1]` / `scholars[]` / `year` / `format`），写到 `v2/data/keiei/kp/{id}.json`
   - **同时**指出现有 v2 数据的 多余 / 错挂 / 缺失 / 命名问题（如学派 themeKey orphan）
   - 遵守 [CONTRIBUTING.md §8](Main/CONTRIBUTING.md) 的 KP 生成 6 原则（先查重、教材优先、样品后批等）
   - 给出**推荐方案 + 理由**，但最终由用户决定

**重要**：卡片生成是**每个 KP 的闭环动作**，不需要用户单独喊"出卡片"；并且**必须走高保真 demo 页**，不能用文字糊弄。

### 5. 语言规则
- 主对话中文
- 专业术语括号附 日本語 + English：如 **有限理性**（限定合理性・Bounded Rationality）
- 日文版数据遵守 CONTRIBUTING.md §2 的学术术语对照表，不直译

### 6. 志望校倾向加料
讲每个 KP 时，在合适处点一下目标校的命题倾向差异（比如"一橋偏好 Barney 原典，慶應偏好 Peteraf"），不用每个 KP 都点。

### 7. 重复 KP 处理流程（2026-04-20 用户立规）
发现数据重复/冲突时，**不能跳过标准颗粒度流程**：

1. **先解决结构问题**：合并 / 拆分 / 重命名 3 选 1 给用户决定
2. **结构定了之后，回到标准 6 步**：
   - 生成 3 颗粒度 demo（必须）
   - 用户选定后才入库
   - 入库后验证 KP JSON 完整（zh + ja 子字段都有）
   - 验证旧 KP id 已删除（git rm 或 admin UI DELETE，~90s sync 后线上消失）
3. **不要因为"结构已改"就省略颗粒度选择**——颗粒度是独立维度
4. **JSON 同步验证**（V2 替代 V1 双文件同步）：
   - `cd v2 && pnpm validate` 确认 zod schema + cross-ref 全过
   - `cat v2/data/keiei/kp/{id}.json | jq '.body'` 确认 zh + ja 长度合理（≥300 字）
   - 确认已删除 KP 的 JSON 文件不在 git 里
   - git log 确认 commit + push 成功，验证报告展示在用户面前

### 8. 表达风格：直接 > 学术（2026-04-20 用户立规）
KP body 和 demo 内容里**避免学术化绕弯表述**，首选直接简单的日常语言：
- 🚫 "稳定才是需要解释的例外" → ✅ "变革是常态，没有终点"
- 🚫 "存在稳定新均衡可达成" → ✅ "变革有明确起止，走完能稳下来"
- 🚫 "组织的内外制约构成的结构性要因" → ✅ "组织内外 6 项具体的阻力"
- **原则**：用户是备考者，考场答案要用**读者第一秒就懂**的语言，不是绕弯显示深度
- **例外**：学者原话专有术语不动（Reliability·Accountability·Episodic·Continuous 这类保留原词+中文解释即可）

### 8. 两级 Callback 机制（2026-04-19 / 2026-04-20 用户要求）

**Level 1 · 短 callback（每 3-4 KP · 方向感）**
- 标注 ✅ 已完成的 KP
- 点出当前在地图上的位置
- 预告下一组要讲的 KP
- 不用完整重贴，拣关键部分就行——主要是给用户"我在哪 / 我走到哪 / 接下来去哪"的方向感
- 时机：在**下一个 KP 开讲前**做，不要打断正在讲的 KP

**Level 2 · 长 review（每 5-10 KP 或间隔 12 小时以上重启 · 内容回忆）**
- 触发条件：① 累计讲了 5-10 个 KP（至少 5 个，不超过 10 个强制触发）；② 会话中断后 12 小时以上重启
- **格式必须是表格或 checklist 形式**（2026-04-24 用户要求）——快速过每个 KP 的关键内容：
  - 每个 KP **1-2 行关键点**（学者·年·核心论点·易混点提醒），表格形式
  - 时间地图 map 串连接即可，**不展开 3 大主线/万能公式/横向穿透线**
  - 易混淆的点 2-3 行 list 即可
- **不要**用几段话系统回顾、不要写主题线深度分析、不要写考场公式——那些过度关联讲解用户不喜欢
- 目的：快速激活记忆点，不是重讲
- 时机：下一个 KP 开讲前，标「📖 Level 2 长回顾」
