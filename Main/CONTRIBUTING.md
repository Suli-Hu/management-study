# 开发规范与经验总结

本文档记录了在开发过程中积累的规范和踩坑经验，供跨对话时参考。

---

## 0. 设计系统——色阶与字重

### CSS变量色阶（5级灰度）

| 变量 | 色值 | 用途 |
|------|------|------|
| `--text-primary` | #1d1d1f | 标题、加粗关键词 |
| `--text-secondary` | #2c2c2e | **正文、描述、卡片文字**（主要阅读文本） |
| `--text-tertiary` | #48484a | 次要信息（英文副标题、手风琴标题） |
| `--text-quaternary` | #86868b | 辅助信息（时间戳、提示文字） |

### 字重规范

| 变量 | 值 | 用途 |
|------|------|------|
| `--weight-regular` | 400 | **正文body**（cn-body默认字重） |
| `--weight-semibold` | 600 | 标题、`<strong>`加粗词 |
| `--weight-light` | 300 | 不再用于正文 |

**原则**：正文字重≥400，颜色≥secondary。如果看起来"太细"或"太浅"，说明层级选低了。

## 1. KP三层信息架构

所有知识点（KP）的body应遵循统一的三层结构：

```
导语（font-weight 400，1-2句：谁+何时+一句话定义）
  ↓
核心内容（理论实质，◆编号或<strong>加粗叙述）
  ↓
评价标签（◆意义——xxx ◆局限——xxx，始终可见不折叠）
```

### 格式选择标准

| 内容类型 | 推荐格式 | 示例 |
|---|---|---|
| 内容量小、因果链型 | **方案C**：导语叙述+`<strong>`加粗关键词 | 防卫性惯例、企业行为理论 |
| 3-5个并列概念 | **◆平铺** | 成就动机理论、双元组织 |
| 多组分类信息 | **`<br>【】`手风琴** | MBO、4I框架 |
| 2-4项对比 | **`<compare>`翻转卡片** | 动机三阶段、CSV vs CSR |
| 2×2矩阵 | **`<quad>`四象限** | BCG矩阵、SWOT、安索夫 |

### KP卡片信息层级

```
标题行：中文名 | 学者标签 | 年份
副标题：English Name / 日本語名（用 / 分隔，三语对照）
   ↓
正文区：直接从内容开始（不放日文名）
```

- 日文名属于**元信息**（叫什么），不属于**内容**（说什么），必须放在副标题区
- 日文名从DATA_JA中自动提取，去掉`<strong>`标签和括号内容后取纯名称
- 正文第一行必须是内容本身，不能是名称标签

### 语义标签规范

- 评价性标签词表：意义、局限、企业例、例子、应对、应用、比喻
- badge显示单字：义/限/例/应/用/喻（日文：義/限）
- 数据格式必须用 `◆意义——xxx`（破折号），不能用 `◆意义：xxx`（冒号会导致标签检测失败）
- 在`<br>【】`折叠组中，评价标签项自动跳出折叠组渲染在外层

### 导语中的`<strong>`加粗

- 导语 font-weight: 400（细体），`<strong>` font-weight: 600
- 只加粗**核心术语和关键结论**，不要全文加粗
- 日文版也要对应加粗相同的关键词

## 2. 日文版规范

### 学术用语
- **绝对不能直接翻译中文**，必须使用日本経営学的标准学术术语
- 每次生成前查证该概念在日文学术文献中的通用表达

### 已知术语对照

| 中文 | 错误日文 | 正确日文 |
|---|---|---|
| 管理人（Administrative Man） | 管理人 | **経営人** |
| 《管理行为》（Simon） | 管理行動 | **経営行動** |
| 探索与利用 | 探索と利用 | **探索と活用** |
| 动态能力三核心 | 感知・把握・転換 | **感知・捕捉・変容** |
| 满意水平（aspiration level） | 満足水準 | **要求水準** |
| 決策論（日文中不存在） | 決策論 | **意思決定論** |

### 表达平易化
用户是写日语小论文的中国留学生，避免生僻表达：

| 避免 | 改用 |
|---|---|
| 網羅的 | 完全な / すべての |
| 奠基的 | 基盤となる |
| 乖離 | ギャップ |
| 賦与 | 設定 / 与える |

## 3. 数据同步规范

### 新建/修改KP时的检查清单

1. **data.js body必须纯中文**，术语附英文/日文用括号标注
2. **data_ja.js必须遵守 `<strong>標題</strong>——正文` 格式**
3. **三处同步**：KNOWLEDGE数组 + 学派concepts数组 + 学者theories数组
4. **schools不允许为空数组**
5. **DATA_JA key = cnKey**（标题去掉尾部所有括号）

### 合并KP时

1. DATA_JA key必须用cnKey（去掉括号后的标题）
2. 删除被合并KP的DATA_JA条目
3. 更新保留KP的DATA_JA内容
4. 用脚本验证cnKey匹配

### 多学者支持

- scholar字段支持逗号分隔：`scholar:"cyert,march"`
- 标题栏自动显示多个独立可点击标签
- `_knScholars(k)` 函数解析

## 4. 卡片表（CardTable）组件

| 组件 | 语法 | 描述 |
|---|---|---|
| 对比卡片 | `<compare>col1\|\|col2\|\|col3</compare>` | 翻转卡片，列数自动适配 |
| 四象限 | `<quad>Y轴,X轴\|\|cell1\|\|cell2\|\|cell3\|\|cell4</quad>` | 支持二分和连续两种模式 |
| 手风琴 | `<br>【标题】<br>①...` | 折叠分组 |
| 平铺列表 | `◆item1◆item2` | 自动编号 |

### compare字段格式
```
title|keyword|desc|type|theories|detail(翻面)
```

### quad二分模式
- 轴格式用 `/` 分隔：`优势/劣势,威胁/机会`
- 每格只有一个字段（纯文本，不翻面）

### quad连续模式
- 轴格式用 `→` 分隔：`市場成長率 低→高`
- 每格4字段：`name|emoji|sub|detail`（有翻面）

### 卡片视觉规范（compare / quad 通用）

| 属性 | 规则 |
|---|---|
| 底色 | `var(--bg-primary)` 白色，不用灰底/米色 |
| 层级感 | `box-shadow: 0 1px 4px rgba(0,0,0,.06)` 微阴影 |
| hover | compare: `translateY(-2px)` 浮起；quad: `scale(1.03)` 放大 |
| 翻面提示 | **不显示**，通过阴影暗示可交互 |
| type pill | **不显示**，type字段仅用于翻面标题（`title · type`） |
| 标题文字 | `--text-primary` (#1d1d1f) |
| 描述/正文 | `--text-secondary` (#2c2c2e)，不能用tertiary或更浅 |
| 底部理论 | `--text-secondary`，与描述同深度 |
| 背面文字 | `--text-secondary` |

## 5. 搜索功能

- 支持中文、English、日本語三语搜索
- 支持kXXX格式的ID搜索
- 日文匹配时自动展开并显示日语版
- 可点击的理论名智能跳转（学者页/知识点/学派页）

---

## 6. 学者颜色自动推导

- `_scholarAccent(s)` 函数从学者的schools数组第一个元素推导颜色
- schools数组中第一个学派决定学者详情页的主题色
- 不再需要手动维护学者的accent字段

---

## 7. 部署规范

- **每次部署前必须征得用户同意**
- Netlify免费套餐每月1000 build credits
- 攒大改版再部署，避免小修改浪费credits
- 部署命令：`npx netlify deploy --prod --dir=.`
- GitHub推送：`git push`（SSH key已配置）
