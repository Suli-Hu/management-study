# KP生成工作流程原则（2026-04-17 用户明确要求）

用户对之前批量生成12个KP不满意。原因：与现有k314重复、深度不够（七种浪费只列名不展开）、没先对齐颗粒度就批量生成。

详细原则已写入项目 `Main/CONTRIBUTING.md` 第8节。要点：

## 核心6原则

1. **先查重，再生成** — 任何新KP前先搜索data.js，发现重复必须AskUserQuestion询问补充/新建/合并
2. **用真实渲染的高保真对比页确认颗粒度** ⭐ — 不允许用文字让用户选颗粒度，必须创建`Main/demo_granularity.html`用网站真实CSS渲染3种方案（A合并/B专题/C独立KP）让用户视觉对比
3. **教材优先，先样后批** — 先做1-2个样品KP确认格式再批量
4. **重复处理规则** — 列表格对比独有内容，取并集合并而非丢弃
5. **正确性验证** — 教材有的直接引用，不确定的标注"待查证"，不装作知道
6. **讨论方式** — 有选项用AskUserQuestion，大批量用Plan模式+plan file

## 禁止事项
- ❌ 用纯文字描述颗粒度让用户选
- ❌ 一次性批量生成10+个KP不经过对齐
- ❌ 不查重直接新建可能重复的KP
- ❌ 不装作了解教材里没有的内容
