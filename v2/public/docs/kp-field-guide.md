## 1. Format 选择指南 — 最重要的一步

写新 KP 第一件事是选 format。**选错 format = 整张 KP 失去结构**。5 种 format 各有清晰边界：

### 1.1 决策树

```
你这个 KP 想表达什么？
│
├─ 单一观点 / 一段连续叙述（无明显内部结构）
│   → narrative
│
├─ 多个并列条目（如 "5 种类型 / 3 个原则 / 4 大要点"），条目之间无层级
│   → flat-list
│
├─ 多个分组，每组有标题 + 组内多条目（明显两层结构）
│   → accordion
│
├─ 多个并列对象做横向对比（如 "X vs Y vs Z 在 5 个维度上"），需要读者扫读对比
│   → compare
│
└─ 内容天然是 2 维矩阵（如 "高/低 × 高/低 = 4 个象限"）
    → quad
```

### 1.2 各 format 详解

#### `narrative` — 叙事

**何时用**：
- 一段或几段连续 prose，无明显并列条目
- 概念定义、理论背景、单一论点
- body 长度通常 100-500 字

**对例**：
- ✅ "代理人理论由 Jensen 与 Meckling 1976 年提出，认为公司是委托人（股东）与代理人（经理）之间一系列契约的集合。代理人有自利倾向，会在信息不对称下追求私利，损害委托人利益。解决之道是设计激励机制 + 监督..."

**何时不用**：
- ❌ 内容明显是 "1, 2, 3, 4..." 平行列表 — 用 flat-list
- ❌ 内容有"组 A 包含 a1/a2，组 B 包含 b1/b2"的两层结构 — 用 accordion

**注意**：占当前 KP 库 70%，是默认格式。**叙事够用就别强加结构**。

---

#### `flat-list` — 条目列表

**何时用**：
- 多个并列条目，每条有明确"名称 + 描述"
- 条目之间无层级、无分组
- 典型如"5 种 X / 3 个 Y / 几大原则"

**对例**：
- ✅ "5 种竞争策略" — 每条 = 一种策略名 + 描述
- ✅ "3 个组织变革阻力来源" — 每条 = 一个来源 + 解释

**何时不用**：
- ❌ 每条又分成多个子条目 — 用 accordion
- ❌ 多个条目要在多维度横比 — 用 compare
- ❌ 只有 1 条 — 直接 narrative

**lead（导语）**：
- 写**总览 / 这 N 条共同回答什么问题**
- 不要重复条目内容
- 例：「消费者比较品牌时不总是完全理性，而会用以下选择规则：」（导语）+ 5 条规则

**条目设计**：
- `name`：简短的条目名（2-10 字）
- `desc`：1-3 句描述。**不要写半页**（半页改用 accordion）

---

#### `accordion` — 折叠分组

**何时用**：
- 内容明显是**两层结构**：分组 + 组内多条
- 每组通常 2-5 条，组数通常 2-5 组
- 典型如"X 理论的 3 个阶段，每阶段 4 个要点"

**对例**：
- ✅ "Lewin 三阶段变革" — 组 1: 解冻 (3 步) / 组 2: 改变 (4 步) / 组 3: 再冻 (2 步)
- ✅ "5 种波特竞争力，每种含定义 + 影响因素 + 对策"

**何时不用**：
- ❌ 只有平行条目，无分组 — 用 flat-list
- ❌ 分组只有 1 个 — 用 flat-list（accordion 至少 2 组）
- ❌ 分组里只有 1 条 — 用 flat-list

**lead**：
- 写**整张 KP 的总主题 / 为什么用这种分组**
- 例：「消费者购买决策按参与程度和品牌差异划分为 4 种行为：」

**groups[].title**：
- 分组名要**清晰且互斥**
- 用学术 / 实务标准命名，不要自创奇怪名字
- 例：✅ "解冻阶段" / ❌ "第一段"

**groups[].items[].name vs desc**：
- name = 子条目核心概念（2-10 字）
- desc = 解释 + 例（1-3 句）
- 如果某条只有 name 没 desc，desc 留空，不要硬填

---

#### `compare` — 横向对比表格

**何时用**：
- 多个并列对象（≥2）需要在**多个维度**上对比
- 读者需要扫读"X 在 d1, d2, d3 上分别是什么"
- 典型如"3 种领导风格的对比 / 古典 vs 行为 vs 系统学派对比"

**对例**：
- ✅ "Mintzberg 5 种组织结构对比" — 5 列 × 6 维度
- ✅ "Y 理论 vs X 理论" — 2 列 × 5 维度

**何时不用**：
- ❌ 只有 1 个对象 — 用 narrative
- ❌ 没有清晰对比维度（只是列举） — 用 flat-list
- ❌ 4 象限 — 用 quad

**字段说明**（每列 6 个字段，不是所有都要填）：

| 字段 | 含义 | 写什么 |
|---|---|---|
| `title` | 列名（被对比的对象） | "X 理论" / "古典学派" |
| `keyword` | 关键词标签 | 提炼对象的标签词，2-4 字 |
| `desc` | 一句话定义 | "认为人是经济人..." |
| `type` | 类型 / 学派归属 | "行为科学" / "决策学派" |
| `theories` | 关联理论 | "需求层次理论 / 双因素理论" |
| `detail` | 详细描述 | 1-2 段补充 |

**lead**：写整体对比的目的（"为什么把这几个放一起对比"）。

---

#### `quad` — 四象限矩阵

**何时用**：
- 内容天然是 2x2 矩阵
- 两个二元维度（高/低、内/外、强/弱…）交叉成 4 个象限
- 典型如"BCG 矩阵 / Ansoff 矩阵 / 4 种购买行为"

**对例**：
- ✅ "BCG 矩阵 — 市场增长率 × 相对市场份额"（明星/现金牛/问题/瘦狗）
- ✅ "复杂性购买行为分类 — 参与程度 × 品牌差异"

**何时不用**：
- ❌ 不是 2 维分类（如 3 个维度、单维度）— 用 compare 或 flat-list
- ❌ 维度不是二元（如低/中/高 三档）— 用 compare

**字段说明**：
- `yAxis`：纵轴标签（如"市场增长率"）
- `xAxis`：横轴标签（如"相对市场份额"）
- `cells`：**必须 4 个**，按"左上 → 右上 → 左下 → 右下"顺序
- 每个 cell:
  - `name`：象限名（如"明星 Star"）
  - `emoji`：可视化 emoji（如 ⭐）
  - `sub`：副标题（高维度组合，如"高增长 + 高份额"）
  - `detail`：1-2 句解释 + 战略建议

**lead**：写矩阵的目的（用什么 2 维做出来 + 想看什么）。

---

### 1.3 选错 format 的常见症状

| 症状 | 改用 |
|---|---|
| narrative 里出现 "1. ... 2. ... 3. ..." 编号列表 | flat-list |
| flat-list 里某些条目又分了 2-3 子条目 | accordion |
| accordion 里只有 1 个 group | flat-list |
| compare 里只有 1 列 | narrative |
| quad 不是 2x2（5 个 cell / 3 个 cell） | flat-list 或 compare |
| evaluations 字段写满了，但 body 几乎空 | KP 没准备好，先写 body 再写 eval |

## 2. Body 内的字段语义

### 2.1 `lead` — 导语（除 narrative 外所有 format 都有）

**定义**：在所有条目 / 分组 / 列 / 象限**之前**的**总起一句**。回答"接下来这堆东西在说什么 / 为什么放一起"。

**对例**：
- ✅（flat-list lead）"消费者比较品牌时不总是完全理性，而会用以下选择规则："
- ✅（accordion lead）"组织变革按 Lewin 经典模型分三阶段，每阶段有不同实施重点："
- ✅（compare lead）"经典管理理论按对人的假设分三大学派："

**错例**：
- ❌ 把第一个条目写成 lead — 例：lead 是"线性补偿型：各属性按重要度加权"。这是条目，不是 lead
- ❌ lead 跟 KP title 重复 — title 已经写了主题，lead 不要复读
- ❌ lead 占半页 — lead 应该 1-2 句，详细内容放进 items / groups

**留空策略**：
- 如果 KP title + 后续条目已经自解释，**lead 可以为空字符串**
- 不要硬凑

---

### 2.2 flat-list 的 `items[].name` vs `items[].desc`

**name**：条目核心概念（2-10 字理论 / 现象 / 类型名）

**desc**：1-3 句的解释 + 简短例（如有）

**对例**：
```
name: "线性补偿型"
desc: "各属性按重要度加权，总分最高者被选择。某一属性弱点可被另一属性强点补偿。"
```

**错例**：
- ❌ name 太长（"线性补偿型决策模型在消费者评价中的应用"）— 截短
- ❌ desc 只有 5 个字（"加权选择"）— 补充足够信息
- ❌ desc 占半页 — 拆成 accordion 里的 items

---

### 2.3 accordion 的 `groups[].title` 和组内 items

**groups[].title**：
- 用学术 / 实务公认的分组命名
- 必须**互斥**（一个内容只属于一组）
- 长度通常 4-12 字

**对例**：
- ✅ "解冻阶段" / "改变阶段" / "再冻阶段"
- ✅ "环境分析" / "战略制定" / "战略实施"

**错例**：
- ❌ "第一组" / "第二组" — 不传递语义
- ❌ "其他" — 兜底分类
- ❌ groups 之间内容 overlap — 想清楚归属

**groups[].items**：跟 flat-list 的 items 同语义。组内通常 2-5 条。

---

### 2.4 compare 的 6 列字段（每个对比对象一组）

每列代表**一个被对比的对象**（如 X 理论、古典学派、Mintzberg 模型）。compare body 含多列（≥2），每列 6 个字段。**不是每个字段都必填**，按需填，空字段渲染时自动隐藏。

#### `cols[].title`（必填）— 对象名

**定义**：被对比对象的核心名字。是这一列的"标题"，渲染在最上方。

**写什么**：用学术 / 实务公认名，简短（2-12 字）。

**对例**：
- ✅ "X 理论" / "Y 理论" / "Z 理论"
- ✅ "古典学派" / "行为学派" / "系统学派"
- ✅ "Mintzberg 简单结构" / "机械式官僚结构"

**错例**：
- ❌ "第一种" / "类型 A" — 没有语义
- ❌ "X 理论关于人性的核心假设和管理含义详细对比" — title 当 desc 用了，太长
- ❌ 留空 — title 必填

**与 keyword 的区分**：title = 这一列**叫什么**（学术名称），keyword = 这一列**最关键的一个标签词**（提炼用，可能不同于 title）。

---

#### `cols[].keyword` — 关键词标签

**定义**：用 1 个词概括该对象**最核心的特征 / 假设 / 立场**。在 UI 上渲染为 chip，让读者扫一眼就抓住对象本质。

**写什么**：2-4 字的提炼词。**不是 title 的同义词，是它的"灵魂关键词"**。

**对例**：
- ✅ X 理论 → "经济人" / Y 理论 → "社会人" / Z 理论 → "复杂人"
- ✅ 古典学派 → "效率" / 行为学派 → "人际关系" / 系统学派 → "整体观"
- ✅ Apple → "极简" / Google → "数据驱动"

**错例**：
- ❌ X 理论 → "X 理论的人性假设" — 不是关键词，是描述
- ❌ "好" / "重要" — 评价词不是特征词
- ❌ 抄 title — 应该提炼

**留空策略**：如果想不出**真正提炼**的关键词，就留空。**不要硬写**「该理论的核心」这种空话。

---

#### `cols[].desc` — 一句话定义

**定义**：用 1-2 句话定义该对象的核心立场 / 主张 / 内容。回答"这一列的对象是什么"。

**写什么**：完整一句话，能让人 grasp 这个对象的本质。

**对例**：
- ✅ X 理论 → "认为人天性懒惰，必须严格控制和惩罚才能让其工作。"
- ✅ Mintzberg 简单结构 → "权力高度集中于战略顶端，小型组织 / 创业期常见，决策快但不适合复杂业务。"

**错例**：
- ❌ "是一种理论。" — 没信息
- ❌ "见 detail" — 应该自包含
- ❌ 写了 3 段 — 那是 detail 的事，desc 留 1-2 句

---

#### `cols[].type` — 类型 / 归属

**定义**：该对象所属的**更大类别 / 学派 / 流派**。提供更高层分类信息。

**写什么**：一个分类标签词。

**对例**：
- ✅ "行为科学" / "决策学派" / "系统理论"
- ✅ "建构主义" / "实证主义"

**错例**：
- ❌ "重要理论" — 不是分类
- ❌ 跟 keyword 重复 — 它们目的不同

**与 keyword 的区分**：type = 这个对象**属于哪个大类**（归属），keyword = 它**自己最特别的标签词**（特征）。

**留空策略**：如果对象不属于任何明显归属（比如新提出的概念）— 留空。

---

#### `cols[].theories` — 关联理论

**定义**：跟该对象**相关 / 互补 / 来源 / 衍生**的其他理论 / 概念。多个用 `/` 或顿号分隔。

**写什么**：理论 / 概念名列表。

**对例**：
- ✅ "需求层次理论 / 双因素理论 / ERG 理论"
- ✅ "5 力模型、价值链、SWOT 分析"

**错例**：
- ❌ "Maslow 1943 / Herzberg 1959 / Alderfer 1972" — 写理论名不是学者
- ❌ "很多相关理论" — 没具体

**留空策略**：找不出明显关联理论 — 留空。

---

#### `cols[].detail` — 详细描述

**定义**：补充段落，对该对象做**深入展开**（背景、机制、批判、案例）。

**写什么**：1-2 段，每段 2-4 句。

**对例**：
- ✅ "X 理论由 McGregor 在 1960 年《企业的人性面》中提出，是对当时管理实践默认人性假设的总结。它直接影响了科层制管理风格 — 严密的考核、外部奖惩、清晰的指令链。X 理论被广泛批评为悲观且自我实现 — 严控制下的员工更容易表现出懒惰，反过来强化了 X 假设。"

**错例**：
- ❌ "详细见教材。" — 应该自包含
- ❌ 跟 desc 重复 — desc 已经写了一句话，detail 应该补充新信息
- ❌ 写 5 段 — 太长，拆分到多个 KP

**留空策略**：能用 desc 一句话说清的对象 — detail 留空。

---

#### compare 字段填写优先级建议

新建 compare KP 时按这个顺序填，最少填到 title + desc 即可可用：

```
title (必填) → desc (强烈建议) → keyword (有则填) → type (有则填) → theories (有则填) → detail (深度补充)
```

**6 个字段全填的列很重，反而模糊**。**按对象需要选 3-5 个填**就好。

### 2.5 quad 的 axes 和 cells

quad 是 2×2 矩阵，由 yAxis × xAxis 两个二元维度切出 4 个象限。

#### `yAxis` / `xAxis` — 轴标签

**定义**：定义矩阵的两个维度名。**必须是互斥的二元划分**（高/低、强/弱、内/外、新/旧）。

**写什么**：写**维度名**（不是高/低本身），渲染层会自动加 ↑↓ 高/低坐标。

**对例**：
- ✅ yAxis: "市场增长率"（→ 渲染为"高增长 ↑ / 低增长 ↓"）/ xAxis: "相对市场份额"
- ✅ yAxis: "参与程度" / xAxis: "品牌差异"
- ✅ yAxis: "战略重要性" / xAxis: "实施难度"

**错例**：
- ❌ yAxis: "高增长 / 低增长" — 写成了高/低对，应该写"市场增长率"让系统自动加高/低
- ❌ yAxis: "绿色 / 红色" — 不是真维度
- ❌ yAxis: "增长 / 速度 / 份额" — 一个轴只能是 1 个维度

**判断标准**：能造句"X 越[高/多]越好"或"按 X [大小]划分"的，是合格维度。

---

#### `cells[]` — 4 个象限（必须正好 4 个）

**顺序固定**（按 cells 数组索引 0-3）：

| 索引 | 位置 | yAxis 维度值 | xAxis 维度值 | 说明 |
|---|---|---|---|---|
| 0 | 左上 | **高** | **低** | y 高 + x 低 |
| 1 | 右上 | **高** | **高** | y 高 + x 高 |
| 2 | 左下 | **低** | **低** | y 低 + x 低 |
| 3 | 右下 | **低** | **高** | y 低 + x 高 |

例（BCG 矩阵，yAxis = 市场增长率，xAxis = 相对市场份额）：
- cells[0] 左上 = "问题 ❓"（高增长 + 低份额）
- cells[1] 右上 = "明星 ⭐"（高增长 + 高份额）
- cells[2] 左下 = "瘦狗 🐕"（低增长 + 低份额）
- cells[3] 右下 = "现金牛 💰"（低增长 + 高份额）

**顺序错了 = 整张矩阵颠倒**，渲染层无法纠正。

---

#### `cells[].name` — 象限名

**定义**：该象限的**学术名 / 通用名**。是这个象限的"身份"。

**写什么**：用业界公认命名，2-6 字。

**对例**：
- ✅ "明星" / "现金牛" / "问题" / "瘦狗"（BCG）
- ✅ "复杂购买" / "和谐购买" / "习惯购买" / "多样购买"（购买行为）

**错例**：
- ❌ "象限 A" / "第一类" — 没语义
- ❌ "高增长高份额型" — 把 sub 当 name 用了；name 应该是简短身份名

**留空策略**：没公认命名时可以临时命名（如"积极投入型"），但**不要留空** — 4 个象限都需要 name 才能区分。

---

#### `cells[].emoji` — 视觉 cue

**定义**：1 个 emoji，让读者快速识别 / 记忆该象限。

**写什么**：1 个 emoji，最好直观映射象限语义。

**对例**：
- ✅ ⭐（明星）/ 💰（现金牛）/ ❓（问题）/ 🐕（瘦狗）
- ✅ 🚀（高速成长）/ 💎（核心资产）/ 🔥（紧急）/ 📦（保守）

**错例**：
- ❌ 🎉🎊✨ — 多个 emoji 堆叠，UI 会乱
- ❌ "明星" — 写文字不是 emoji
- ❌ ⭐⭐⭐ — 重复

**留空策略**：想不出贴切 emoji 就留空，不要硬塞不相关的（🌈🌟之类的）。

---

#### `cells[].sub` — 维度组合副标题

**定义**：用一句话点出该象限**对应的两个维度值组合**。让读者立即明白"这象限为什么在这位置"。

**写什么**：格式通常 `<yAxis 高/低> + <xAxis 高/低>`。

**对例**：
- ✅ "高增长 + 高份额"（明星象限）
- ✅ "低增长 + 高份额"（现金牛）
- ✅ "高参与 + 大差异"（购买行为复杂购买）

**错例**：
- ❌ "属于明星象限" — 重复 name 信息，没新信息
- ❌ "增长高，份额高" — 不够 punchy，建议简洁短语
- ❌ 留空 — sub 是矩阵阅读的关键 cue，强烈建议填

---

#### `cells[].detail` — 特征 + 战略建议

**定义**：1-2 句深度信息：该象限的**典型特征 + 该怎么对待它的战略建议**。

**写什么**：先描述特征（这种 case 长什么样），再给行动建议（该怎么做）。

**对例**：
- ✅（明星）"业务势头强，需大量投入维持竞争优势。建议：持续加大资源 + 准备转化为现金牛。"
- ✅（瘦狗）"低增长低份额业务，盈利能力弱。建议：剥离 / 收缩 / 维持现金流，不再追加投资。"
- ✅（习惯购买）"消费者低参与且品牌差异不显著，购买靠习惯。建议：通过低成本广告维持 brand recall + 货架可见性。"

**错例**：
- ❌ "这是一种象限。" — 无信息
- ❌ "需要小心处理。" — 没具体建议
- ❌ 只写特征不写建议（或只写建议不写特征）— 都给

---

#### quad 字段填写优先级

```
yAxis + xAxis (必填，两轴名)
↓
cells[].name (4 个象限名，必填，否则没法区分)
↓
cells[].sub (强烈建议，矩阵阅读 cue)
↓
cells[].detail (主体内容)
↓
cells[].emoji (锦上添花)
```

## 3. Evaluations 6 字段语义

> **重要**：实测中 AI agent 经常把这 6 个字段写成"如何用这个 KP 答题"，导致评价空洞。**写之前必读这一节**。

每个 KP 的 `evalContent.zh` 是 dict，含 6 个 key。**所有字段都可选**（不写就不显示），但写就要符合语义。

### 3.1 `义` (meaning) — 意义

**定义**：该 KP 在**学术史 / 实务上的贡献和价值**。回答"这个理论为什么重要 / 为什么被记住"。

**对例**：
- ✅ "首次系统化提出消费者非理性选择行为的认知模型，挑战古典经济学完全理性人假设。"
- ✅ "把企业战略与组织能力对齐写成可操作框架，是战略落地理论的奠基。"

**错例**：
- ❌ "把相关术语合成一个可直接论述的考试框架。" — 这是 KP 元描述，不是理论意义
- ❌ "适合在期末论述题中使用。" — 这是 KP 用法，不是理论意义

**与"用"的区分**：义 = 学术 / 实务**贡献**（why important），用 = 实务**应用场景**（when used）。

---

### 3.2 `限` (limit) — 局限

**定义**：该 KP 理论本身的**不足 / 边界 / 被批判的点**。回答"这个理论在什么情况下不成立 / 被人挑战"。

**对例**：
- ✅ "假设消费者能清楚意识到自己的选择规则，但实际中很多决策是潜意识的；规则切换的触发机制未充分解释。"
- ✅ "战略-能力对齐的框架在实证研究中难以量化，主要靠案例归纳。"

**错例**：
- ❌ "细节会随题目不同而变化，需结合案例判断。" — 这是答题注意事项，不是理论局限
- ❌ "需要更多研究。" — 太泛、无信息

**判断标准**：能写"X 学者在 Y 年批判了这一点……"的，就是 limit；只能写"用的时候要小心"的，不是 limit。

---

### 3.3 `例` (example) — 例子

**定义**：能体现该 KP 的**真实企业案例 / 事例**。**具体到公司、产品、行业、时间**。

**对例**：
- ✅ "Apple 的产品决策常用辞书编纂型（设计美感属性优先），小米常用线性补偿型（性价比加权）。"
- ✅ "Toyota 1970s 推行的 TQM 是该理论的实证案例。"

**错例**：
- ❌ "适合在论述题中作为分类轴使用。" — 这是 KP 的用途，不是案例
- ❌ "可以举一些企业的例子。" — 没有具体案例
- ❌ "广义上，所有公司都用这个。" — 没具体性

**判断标准**：能查到的具体公司 / 产品名 + 具体行为，才算 example。

---

### 3.4 `应` (response) — 应对

**定义**：基于该 KP，**企业 / 个体应该采取的应对策略 / 处方**。回答"知道这个理论后，我应该做什么"。

**对例**：
- ✅ "品牌应识别目标客户使用的选择规则类型，针对性地强化关键属性 — 例如对辞书编纂型用户主推首要属性的领先地位。"
- ✅ "面对组织变革阻力，先识别 Lewin 三阶段，针对'解冻'阶段单独设计沟通方案。"

**错例**：
- ❌ "用于解释概念关系、比较类型并连接企业案例。" — 这是用法描述
- ❌ "需要应对市场变化。" — 没具体方法

**与"用"的区分**：应 = **该怎么做**（prescriptive action），用 = **在什么场景下用**（when applicable）。

---

### 3.5 `用` (application) — 应用

**定义**：该 KP 的**实务应用场景**。回答"这个理论在哪些工作场景下有用"。

**对例**：
- ✅ "广告设计：根据目标客户的主导规则调整核心 messaging；产品定位：明确强项属性匹配辞书编纂型客户。"
- ✅ "新员工入职 90 天计划设计 / 跨文化合并案例分析。"

**错例**：
- ❌ "用于答题。" — 这是 KP 元用途
- ❌ "广泛应用。" — 太泛

**与"应"的区分**：用 = **场景列表**（在哪些 context 用），应 = **行动指南**（具体该怎么做）。

---

### 3.6 `喻` (analogy) — 比喻

**定义**：让人**快速记住该 KP 的比喻 / 类比**。用日常熟悉的事物映射理论。

**对例**：
- ✅ "线性补偿型 = 加权平均成绩单；连结型 = 入学最低分线；辞书编纂型 = 词典查字（按重要顺序逐项过滤）。"
- ✅ "组织文化 = 冰山 — 露出水面的是行为规范，水下是价值假设。"

**错例**：
- ❌ "类似于一种选择方式。" — 不是比喻
- ❌ 直接重复定义而不映射熟悉事物

**判断标准**：能让没学过这个理论的人在 10 秒内 grasp，才算合格 analogy。

---

### 3.7 6 字段速查对比

| 字段 | 一句话 | 写不出来时怎么办 |
|---|---|---|
| 义 | 学术贡献 | 想"这个理论为什么进了教科书" |
| 限 | 理论的弱点 | 想"哪个学者批判过它" |
| 例 | 真实公司案例 | 想"哪家公司这么干过" |
| 应 | 该怎么做 | 想"作为决策者，下一步动作是什么" |
| 用 | 用在哪些场景 | 想"哪些实务工作里要用到它" |
| 喻 | 形象记忆 | 想"它像生活中的什么" |

**不会写就留空**。

## 4. 关联字段

### 4.1 `schools: string[]` — 所属学派

**必填**，至少 1 个，最多通常 2-3 个。

**怎么决定**：
- KP 主要属于哪个学派的理论体系？写主属
- 跨学派的 KP 可以多选（如"双元能力"既属战略学派也属组织学习）
- **不要乱填多个**：一个 KP 通常清晰属于 1-2 个学派

**写之前**：
- 先调 `GET /api/metadata?discipline=<key>` 拿合法 schools key 列表
- 不能写新学派 — 必须先创建 school
- key 是 lowercase + underscore（如 `pricing_strategy`），不是中文

**对例**：
- ✅ `["consumer_behavior"]`
- ✅ `["change_management", "leadership"]`（双重归属）

**错例**：
- ❌ `["消费者行为"]`（不是 key 是中文名）
- ❌ `["consumer_behavior", "marketing", "strategy", "research"]`（过度归类）

---

### 4.2 `scholars: string[]` — 关联学者

**可选**（默认 []），通常 1-3 个核心学者。

**怎么决定**：
- 这个 KP 的提出者 / 主要发展者是谁？
- 不是"学过这个理论的所有学者"，是**实质贡献者**

**写之前**：
- 先 `GET /api/metadata` 拿 scholars key 列表
- 不存在的学者必须先创建

**对例**：
- ✅ `["howard", "bettman"]`（消费者选择规则的提出者）
- ✅ `["porter"]`（5 力模型的创立者）

**错例**：
- ❌ `["howard", "bettman", "porter", "kotler", "...", ...]`（凑数加无关学者）

---

### 4.3 `tags: string[]` — 颜色标签

**可选**（默认 []）。tags 是 discipline 维护的色彩库，每个 tag 有自己颜色。

**怎么决定**：
- 这个 KP 适合用哪些**主题色**分类？
- 通常 1-3 个 tag
- 多 tag 时，第一个 tag 决定 KP 的"主色"

**写之前**：
- 先 `GET /api/metadata` 拿 tags 列表（含 label + color）
- 不存在的 tag 不能凭空创建（admin 在 discipline 配置加）

**对例**：
- ✅ `["consumer choice", "decision rule"]`

**错例**：
- ❌ `["重要", "考点"]`（tag 应该是主题分类，不是评价词）
- ❌ `["xyz_random_tag"]`（不在 tags 库里的）

---

### 4.4 `year: string` — 年份

**必填**，但**默认空字符串 `""`**也合法。

**怎么决定**：
- 该 KP 提出的代表年份（论文 / 著作发表时间）
- 跨多年的可写时段："1980s" / "1947–1958"

**对例**：
- ✅ `"1979"` / `"1980s"` / `"1947–1958"` / `""`（无明确年份）

**错例**：
- ❌ `"1979 年"`（不要带"年"字，渲染会自动加）
- ❌ `"unknown"`（用 `""` 表示未知）

---

### 4.5 `themeKey: string`（仅 School / View 用，不是 KP 字段）

KP 没有 themeKey 字段；该字段属于 School。

---

## 5. 元字段

### 5.1 `id`

- KP id，全 discipline 内唯一
- 格式 `^[a-z]{1,3}\d+$`（如 `k628`、`m178`、`hr042`）
- 通常前缀 = discipline 首字母（k=keiei, m=marketing 等）
- API 写入时**可省略**，服务端自动生成；显式给的也接受

### 5.2 `discipline`

- 由服务端写入，body 里给了**会被忽略**
- 通过 query param `?discipline=<key>` 指定 tenant 即可

### 5.3 `createdAt` / `updatedAt`

- ISO 8601 字符串
- **服务端强制刷为 now**，body 里给了无效
- 不用写

## 6. 常见错误一览

| 错误 | 修法 |
|---|---|
| 选了 narrative 但内容明显是列表 | 改 flat-list |
| 选了 flat-list 但条目里有子结构 | 改 accordion |
| accordion 只有 1 组 | 改 flat-list |
| compare 只有 1 列 | 改 narrative |
| quad 不是 4 cell | 改 flat-list 或 compare |
| body 里第一条没 name 当 lead 用 | 把它移到 lead 字段 |
| evaluations 6 字段全写"用法描述" | 重读 §3，按定义重写 |
| schools / scholars 写中文名而非 key | 调 `/api/metadata` 拿 key |
| year 写"1979 年" | 改 `"1979"` |
| 强行填空 evaluations 字段凑数 | 留空 |

## 7. 写新 KP 的标准 workflow

```
1. 决定 format（§1 决策树）
2. 调 GET /api/metadata?discipline=<key> 拿 schools/scholars/tags key 字典
3. 起手 GET /api/kps/empty-body?format=<chosen>（v0.8 起）拿空白 body 模板
4. 填 body（按 format 的字段语义 §2）
5. 填 evaluations（按 §3 的 6 字段定义，写不出留空）
6. 填关联字段（schools, scholars, year, tags）
7. 调 POST /api/kps（新建）或 PATCH /api/kps/:id（编辑）
8. （重要）保存后从详情页 review，确认渲染符合预期
```

如果不符合预期 → **不要硬改其他字段凑数**，回到 §1 重新选 format 或回到 §3 重读 evaluations 定义。
