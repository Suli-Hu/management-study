## 2. Deferred to Stage 4

### F4 (P3) — `classifyZodFailure` 非 body 字段归类错

**位置**：[v2/src/lib/kp-legacy-detector.ts](../src/lib/kp-legacy-detector.ts) `classifyZodFailure`

**现象**：当 zod fail 在 schools / title / id 等非 body 字段时，path 不触及 body → 默认归 `body_structure_invalid`，但实际错跟 body 无关。`detail.issues` 有完整 zod path/message 可定位，影响仅 reason 不准。

**修法（Stage 4）**：默认归 `schema_invalid`，仅 path 触及 body 时归 `body_structure_invalid`。需 [migration-v0.8.md §7](../public/docs/migration-v0.8.md#7-错误码表) 错误码表加 `schema_invalid` 行。

### F5 (P2) — schema 允许 `zh.format != ja.format`

**位置**：[v2/src/schemas/kp-api.ts](../src/schemas/kp-api.ts) `KpBodyBilingual`

**现象**：zod 允许 zh/ja 各自独立选 format（`migration §FAQ Q4` 写"产品上强制一致，schema 允许灵活"）。但 [`deriveDualWriteCols`](../src/lib/kp-api-store.ts) 旧列 `format` / `body_format` 都只记 `body.zh.format`，ja 那面信息丢失。

**影响**：v0.7.x 旧 reader（如果还有）只能看到 zh format。Stage 5 drop 旧列后自然消失。老师 agent 按文档"产品上强制一致"行事永远不踩。

**修法（Stage 4）**：选其一
1. schema refine：`.refine((b) => b.ja === undefined || b.zh.format === b.ja.format, '...')` 强制
2. 编辑器侧 UI 永远同步切 zh/ja format（不暴露 schema 灵活性给用户）
3. 不动（可接受，Stage 5 后无意义）

PM 倾向 (2) — schema 灵活性是为了 backwards-compat 的演进空间，强制了反而锁死。
