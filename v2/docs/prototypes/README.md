# Prototypes

静态产品样机放在这里，用来评审信息架构和交互流程，不代表最终实现代码。

## Stage 3 Admin MVP

文件：

- `stage-3-admin-console-demo.html`

打开方式：

1. 在浏览器里直接打开该 HTML。
2. 评审重点：
   - 是否保留 v2 的三个后台场景：学科管理、用户权限管理、API Tokens。
   - 学科管理是否只处理学科元数据，不再承担 Token 生成和单学科权限主流程。
   - 学科列表是否能看见编辑者 / 只读者摘要，但不被“负责人”字段干扰。
   - 用户权限是否仍是“用户 × 学科”的矩阵，且只展示 `无 / 只读 / 编辑 / ALL`。
   - API Token 是否保留名称、关联用户、学科范围、有效期、一次性明文、撤销。
   - 用户展示是否优先用昵称 / 短名，邮箱只作为辅助信息。
   - “含内容不可删”的保护是否还保留。
   - Stage 3 新增的“线上立即生效 / 不需要 GitHub”提示是否够轻。
   - 顶部返回是否应使用“返回”，而不是固定“返回首页”。

说明：

- 这是纯静态 demo，不连接后端。
- 按钮只做本地交互演示，包括 tab、权限矩阵、Token 生成 / 撤销、drawer 和删除确认。
- MVP 暂不引入 `owner / editor / viewer` 产品角色；页面直接写“只读”“编辑”，`ALL` 表示超级管理员。
- 视觉方向是沿用当前 v2 admin 页，做渐进式重构，不做大改版。
